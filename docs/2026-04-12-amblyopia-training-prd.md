## 1. Overview（产品概述）

### 1.1 背景

弱视（Amblyopia）是儿童期常见的视觉发育障碍，发病率约为 2%~4%。常规治疗手段包括遮盖疗法（CAM 疗法）、光学矫正及手术干预，但传统训练形式单一、依从性低，导致部分儿童训练效果不理想。近年来，基于数字化手段的视功能训练因趣味性强、参数可量化、便于家庭化部署而受到眼科临床的关注。

### 1.2 问题与机会

- 现有家庭弱视训练工具多为单机软件或移动端 App，功能分散，缺乏系统性训练体系。
- 传统训练难以在趣味性和医学规范性之间取得平衡，儿童依从性差。
- 缺乏可追踪、可量化的家庭训练数据，家长无法实时了解训练进展。
- 医疗级训练软件多为医院专用系统，缺乏面向家庭场景的跨平台产品。

本产品定位为**面向家庭的医学级弱视训练平台**，通过游戏化训练、多维度视觉刺激和完整的家庭管理功能，填补这一空白。

### 1.3 产品定位

一款符合眼科医学训练标准的弱视训练 Web 应用，以游戏为载体，为 3~6 岁儿童提供家庭化视觉功能训练，同时为家长提供训练管理、数据追踪和报告输出能力。

---

## 2. Goals（目标）

### 2.1 业务目标

- 在产品上线后 6 个月内实现注册家庭用户数 ≥ 5,000。
- 用户周活跃训练频次 ≥ 3 次/周（医学建议最低频率）。
- 家长端报告查阅率 ≥ 60%（通过数据证明产品价值）。
- 支持医院/诊所将本产品作为家庭训练处方工具使用。

### 2.2 用户目标

**儿童用户：**
- 在游戏中完成视觉训练任务，获得成就感与奖励。
- 训练过程自然愉快，不将其视为"治疗"。

**家长用户：**
- 便捷地为孩子配置训练计划，无需医学背景知识。
- 清晰了解孩子的训练频次、进度和视力改善曲线。
- 必要时可将训练数据分享给主治医生作为参考。

### 2.3 医学目标

- 训练内容设计遵循国家眼科临床指南及国际弱视研究共识（ICO、AAO）。
- 支持单眼训练（遮盖优势眼）与双眼同视训练（双眼协调）两种模式，适配不同治疗阶段。
- 游戏刺激参数（空间频率、对比度、目标尺寸等）可调节，符合视功能训练规范。

---

## 3. Non-Goals（本次不做）

- 不提供眼科诊断服务，不替代专业医疗检查。
- 不支持实时视频问诊或医生远程干预。
- 不在儿童端直接接入社交功能（评论区、好友系统等）。
- 不支持第三方硬件设备（如眼动仪、VR 头显）的集成（后续版本可探索）。
- 不面向单机型/无网络环境设计（需联网使用）。

## 4. Target Users（目标用户）

### 4.1 儿童用户

| 属性 | 描述 |
|------|------|
| 年龄 | 3~6 岁 |
| 认知水平 | 处于前运算阶段，理解简单指令，依赖视觉引导 |
| 操作能力 | 可在家长辅助下完成触屏/鼠标点击操作 |
| 动机特征 | 偏好即时奖励、卡通形象、声音反馈 |
| 典型场景 | 在家长陪同下，每天完成 15~30 分钟训练 |

### 4.2 家长用户

| 属性 | 描述 |
|------|------|
| 角色 | 患儿监护人（父母、祖辈），或家庭管理员 |
| 医学背景 | 多数无眼科专业背景，依赖产品引导 |
| 数字素养 | 中等；熟悉主流移动设备操作 |
| 核心诉求 | 简便配置训练、安全监管、数据可见 |
| 典型场景 | 上下班间隙查看孩子训练报告，在复诊前导出数据 |

### 4.3 医生用户（可选，管理系统角色）

眼科或小儿眼科医生，可通过家长分享的报告了解家庭训练执行情况，不直接登录本产品。

## 5. Scope（范围）

### 5.1 核心功能（Core）

| 功能模块 | 描述 |
|----------|------|
| 儿童端训练模块 | 10 款弱视训练游戏，支持单眼/双眼模式 |
| 家长端管理模块 | 家庭成员管理、训练计划配置、游戏参数调节 |
| 数据追踪模块 | 训练记录、频次统计、进步曲线、报告生成 |
| 账号与权限模块 | 家庭账号体系，儿童/家长角色区分 |
| 响应式前端 | PC / 平板 / 手机跨设备自适应 |

### 5.2 可选功能（Future）

- 医生端入口（数据报告查阅）
- 社区/激励系统（连续训练徽章）
- AI 自适应训练难度调整

- 产品为**辅助训练工具**，不声称治疗效果，不替代医师诊疗。
- 所有游戏内容均为纯前端实现，不依赖特殊硬件。
- 数据存储采用云端数据库（支持多端同步），需联网使用。

## 6. User Flow（用户流程）

### 6.1 首次注册与配置流程

```
家长打开应用
  → 注册家庭账号（手机号/邮箱）
  → 添加儿童成员（姓名、年龄、弱视类型、治疗阶段）
  → 选择训练模式（单眼遮盖 / 双眼同视）
  → 系统推荐初始训练计划
  → 开始训练
```

### 6.2 日常训练流程

```
儿童打开应用（选择角色）
  → 进入游戏大厅（展示可用游戏）
  → 选择或由系统推荐游戏
  → 选择本次训练背景参数（空间频率）
  → 开始训练（游戏内含标准时长控制）
  → 训练完成（展示星星/奖励）
  → 数据自动上传
```

### 6.3 家长管理流程

```
家长登录
  → 查看训练报告（本周/本月/整体进步曲线）
  → 调整训练计划（游戏频率、时长、难度）
  → 管理家庭成员（添加/移除儿童账号）
  → 导出训练报告（PDF/图片）
  → 设置提醒（每日训练提醒）
```

## 7. Requirements（功能需求）

### 7.1 游戏总体设计规范

每款游戏均需满足以下通用规范：

- **单局时长：** 3~8 分钟（根据游戏类型可配置）
- **视觉反馈：** 即时得分、连击奖励、失败提示、完成后星级评定
- **音频反馈：** 背景音乐（可关闭）、操作音效、胜利/失败语音提示
- **进度保存：** 游戏中途退出自动保存进度，30 秒内可继续
- **参数可调：** 空间频率、对比度、目标尺寸、游戏速度均可由家长端配置
- **无内购：** 儿童端不出现任何付费入口

---

### 7.2 十款游戏详细设计

#### 游戏 1：条纹追踪（Stripe Chase）

**训练类型：** 视觉追踪
**医学原理：** 慢速移动的条栅刺激视皮层神经元，提升追视功能
**玩法描述：** 屏幕显示不同方向的条栅背景，目标物（卡通小鱼）在条栅中沿固定轨迹移动。儿童通过触摸/点击跟随目标移动轨迹，或在目标经过指定区域时点击捕捉。目标移动速度可调（慢/中/快三档）。
**参数配置：** 条栅方向（水平/垂直/斜向）、移动速度（0.5~3 deg/s）、目标尺寸（1~4 deg 视角）
**空间频率档位：** 低频（0.5 cyc/deg）、中频（2 cyc/deg）、高频（4 cyc/deg）

---

#### 游戏 2：光斑消消乐（Dot Pop）

**训练类型：** 眼手协调 / 对比度感知
**医学原理：** 高对比度光斑刺激视网膜中央凹，提升精细定位能力
**玩法描述：** 在纯色或条栅背景上随机出现多个彩色光斑（红/蓝/绿）。儿童需要在限定时间内用手指/鼠标点击所有同颜色光斑（如"点击所有红色光斑"）。随关卡推进，背景加入网格或条纹干扰，光斑数量增加，尺寸减小。
**参数配置：** 光斑对比度（10%~90%）、背景类型（纯色/条纹/网格）、目标颜色数量（1~3 色）

---

#### 游戏 3：融合小拼图（Fusion Puzzle）

**训练类型：** 双眼融合
**医学原理：** 通过分视图片（左眼/右眼分别接收不同信息）强迫双眼协同，训练融合功能
**玩法描述：** 屏幕左右两侧分别显示拼图的一半（采用红蓝分视或偏振分视原理，在浏览器中通过色彩叠加实现融合效果），儿童需将左右两半拼图对齐完成拼图。双眼同视模式下，两侧图片存在微小位移，需要融合才能看到完整图像。
**参数配置：** 左右视差角度（5~20 arcmin）、拼图块数（3×2 / 4×3 / 5×4）

---

#### 游戏 4：记忆翻翻卡（Memory Flip）

**训练类型：** 视觉认知 / 短期记忆
**医学原理：** 训练视觉信息短时存储与再认能力，间接强化视皮层处理效率
**玩法描述：** 屏幕展示 4×3 或 5×4 网格的反面卡片，卡片正面为卡通动物/水果图案。先整体显示 3 秒，然后全部翻至背面。儿童按顺序回忆并点击之前看到的目标图案。
**参数配置：** 卡片数量（6/8/12/15 张）、显示时长（1~5 秒可调）、背景复杂度

---

#### 游戏 5：眼手画线（Draw the Line）

**训练类型：** 眼手协调 / 精细运动
**医学原理：** 要求儿童沿视觉引导的路径绘制，训练手眼协调与路径追踪能力
**玩法描述：** 屏幕上显示一条虚线路径（直线、弧线或折线），路径上随机出现障碍物。儿童用手指或鼠标沿路径从起点画到终点，路径经过背景条栅区域。路径总长度和障碍物数量随关卡推进增加。
**参数配置：** 路径类型、路径长度（50~300 px 等效视角）、背景条栅频率、障碍物密度

---

#### 游戏 6：调节升降台（Accommodation Lift）

**训练类型：** 调节功能
**医学原理：** 通过目标物在不同距离的交替出现，训练眼睛的调节幅度与灵活性
**玩法描述：** 屏幕中显示一个卡通热气球目标，背景为远处山峦/近处草地分层场景。目标物大小会周期性放大（模拟近物）和缩小（模拟远物），儿童需要在目标物"变近"（大）时点击屏幕下方的"近"按钮，在目标"变远"（小）时点击"远"按钮。目标切换速度可调。
**参数配置：** 目标切换周期（3~10 秒）、目标尺寸变化比（1.5×~4×）、对比度

---

#### 游戏 7：空间频率连连看（SF Matching）

**训练类型：** 空间频率感知 / 对比度辨别
**医学原理：** 通过匹配不同空间频率的条纹图案，训练视觉系统对空间细节的分辨能力
**玩法描述：** 屏幕显示多个卡片，每个卡片背面隐藏不同空间频率（条纹粗细）的图案。儿童需要找到两个空间频率相同的卡片并配对。游戏过程中背景可切换为不同对比度的纯色或网格。
**参数配置：** 条纹空间频率（0.5 / 1 / 2 / 4 / 8 cyc/deg）、卡片数量（6/8/12）、对比度（低/中/高）

---

#### 游戏 8：立体积木拼（Depth Blocks）

**训练类型：** 立体视 / 深度感知
**医学原理：** 通过红蓝分视呈现存在视差的左右图，训练儿童的立体视功能（双眼视差感知）
**玩法描述：** 屏幕显示一组卡通积木，红蓝分视叠加效果使积木呈现"浮起"和"凹陷"的立体感。儿童需要按从近到远的顺序依次点击积木，将其排列为正确的深度顺序。
**参数配置：** 视差大小（10~40 arcsec）、积木数量（3/4/5 个）、背景复杂度

---

#### 游戏 9：视觉搜索迷宫（Visual Search Maze）

**训练类型：** 视觉搜索 / 扫视
**医学原理：** 通过在复杂背景中快速定位目标，训练扫视功能和视野周边感知
**玩法描述：** 迷宫中有多个岔路和障碍物，卡通角色（小狐狸）位于起点，食物/宝物位于终点。背景叠加条栅或网格。儿童需要在条栅背景下，快速扫视并找到通往终点的正确路径。存在多个干扰岔路和视觉陷阱。
**参数配置：** 迷宫规模（小/中/大）、背景类型（条纹/网格/随机）、干扰物数量

---

#### 游戏 10：快速对对碰（Quick Match）

**训练类型：** 交替抑制解除 / 认知速度
**医学原理：** 快速呈现交叠的视觉刺激，训练双眼信息竞争时的协调处理能力
**玩法描述：** 屏幕快速交替闪现两组图像（左眼图/右眼图各一幅，交替显示，频率 3~8 Hz）。儿童需要快速辨认并选择看到的目标图像是什么。初期速度慢，随训练进度逐步加快。
**参数配置：** 交替频率（3~10 Hz 可调）、显示时长（500 ms~2 s）、目标复杂度

### 7.3 游戏背景与空间频率设计规范

#### 7.3.1 背景类型

| 背景类型 | 参数 | 医学用途 |
|----------|------|----------|
| 纯色背景 | 颜色可调（白/灰/蓝/绿） | 低干扰基础训练 |
| 水平条纹 | 空间频率 0.5/1/2/4 cyc/deg | 水平向视觉刺激 |
| 垂直条纹 | 空间频率 0.5/1/2/4 cyc/deg | 垂直向视觉刺激 |
| 斜向条纹 | 45°/135° 定向 | 斜向视觉功能 |
| 网格背景 | 线宽 2~8 px，间距可调 | 空间位置感知 |
| 随机点阵 | 点密度 5~20 dots/deg² | 杂乱背景下的目标搜索 |
| Gabor 斑 | sigma 1~4 deg，空间频率可调 | 精细对比度感知（高阶） |

#### 7.3.2 空间频率档位定义

| 档位 | 低频 | 中频 | 高频 |
|------|------|------|------|
| cyc/deg | 0.5 | 2.0 | 4.0 |
| 适用阶段 | 初始训练/低龄 | 进阶训练 | 强化训练 |
| 视觉系统 | 棒状细胞为主 | M/P 细胞协同 | P 细胞精细加工 |

#### 7.3.3 对比度档位

| 档位 | 低对比度 | 中对比度 | 高对比度 |
|------|----------|----------|----------|
| Michelson 对比度 | 10% | 40% | 80% |

### 7.4 单眼 / 双眼训练模式设计

#### 7.4.1 单眼训练模式

- **使用场景：** 遮盖优势眼，强制使用弱视眼进行训练（传统遮盖疗法）。
- **实现方式：** 家长端选择"单眼训练"并指定训练眼（左/右）。界面显示引导遮盖动画，提示未训练眼需遮盖。未选择的眼睛对应的游戏内容不呈现（如分视图片仅呈现单眼侧）。
- **遮盖提示：** 每次进入单眼训练前，显示友好的遮盖引导界面（动画演示如何贴眼贴）。
- **单眼专属游戏：** 游戏 1、2、5、6、9 优先用于单眼训练。

#### 7.4.2 双眼同视训练模式

- **使用场景：** 双眼视功能已有基础，需训练双眼协同、融合及立体视。
- **实现方式：** 游戏内容同时呈现双眼信息，分视图片通过红蓝叠加或偏振效果实现融合（如游戏 3、8、10）。
- **双眼专属游戏：** 游戏 3（融合）、游戏 8（立体视）、游戏 10（交替抑制解除）必须使用双眼模式。
- **融合难度递进：** 初始视差角度小（10 arcmin），随训练进度逐步增加至 40 arcsec。

### 7.5 后台管理系统功能设计

#### 7.5.1 家庭账号管理

| 功能 | 描述 |
|------|------|
| 注册登录 | 手机号 + 验证码 / 邮箱注册，支持微信第三方登录 |
| 家庭成员管理 | 最多添加 4 名儿童账号；支持家长账号互相协助管理 |
| 儿童档案 | 姓名、性别、出生日期、弱视类型（屈光不正性/斜视性/形觉剥夺性）、诊断日期、治疗阶段 |
| 治疗阶段标签 | 初训期 / 强化期 / 维持期（三档可调） |
| 多设备同步 | 同一账号可在多个设备登录，数据实时同步 |

#### 7.5.2 训练计划管理

| 功能 | 描述 |
|------|------|
| 每日训练计划 | 设置每日训练时长（15~45 分钟，默认 20 分钟）和训练频次 |
| 游戏组合 | 从 10 款游戏中选择纳入计划的游戏，设置每款游戏的训练比例 |
| 训练时段 | 设置允许训练的时间窗口（如 9:00-11:00，19:00-20:30） |

## 13. Handoff（交接说明）

### 13.1 技术架构提示

- **前端推荐技术栈：** Vue 3 + Vite + TypeScript，响应式 CSS（Tailwind CSS 或自研设计系统）
- **游戏引擎：** 优先使用纯 Canvas 2D 或轻量游戏引擎（如 Phaser），避免引入过重依赖
- **后端推荐技术栈：** Node.js（NestJS）或 Python（FastAPI），关系型数据库（PostgreSQL），Redis 缓存
- **分视效果实现：** 红蓝分视（Anaglyph）可通过 CSS 滤镜实现，无需特殊硬件
- **移动端适配：** WebView 封装（微信小程序/独立 App 形态）为后续商业化路径预留

### 13.2 数据库设计关键实体

```
Family (家庭账号)
Child (儿童档案) → FK: Family
TrainingSession (训练会话) → FK: Child
GameRecord (游戏记录) → FK: TrainingSession
GameConfig (游戏参数配置) → FK: Child, Game
TrainingPlan (训练计划) → FK: Child
ProgressReport (进步报告) → FK: Child
```

### 13.3 关键依赖与里程碑

| 阶段 | 内容 | 预计工期 |
|------|------|----------|
| Phase 1 | 基础框架 + 账号体系 + 家长端管理后台 | 6 周 |
| Phase 2 | 10 款游戏开发（独立模块化）+ 单眼/双眼模式 | 10 周 |
| Phase 3 | 数据追踪 + 报告系统 + 进步曲线 | 4 周 |
| Phase 4 | 跨平台适配优化 + 安全加固 + UAT | 4 周 |
| **合计** | | **24 周** |

### 13.4 给 dev 的特别提示

1. **游戏模块必须参数化：** 所有游戏难度参数（空间频率、速度、对比度）必须从配置表读取，不能硬编码。
2. **分视效果的安全处理：** 红蓝分视图片对色盲用户不友好，需在家长端提供"色觉辅助模式"开关。
3. **儿童数据合规：** 所有儿童数据字段需标注"敏感数据"标签，存储和传输均需加密。
4. **帧率监控：** 游戏运行时需监控实际帧率，若持续低于 24 fps 自动降级画质并记录日志。
5. **离线容灾：** 建议引入 Service Worker 缓存最近 3 次训练数据，防止网络中断导致数据丢失。
